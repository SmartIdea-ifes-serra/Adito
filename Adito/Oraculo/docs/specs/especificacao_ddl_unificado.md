## 1. Visão Geral das Decisões de Arquitetura

1. **Diagrama Canônico:** Apenas o diagrama unificado final (`ModeloCore_SRC_DGP_SIGPESQ_LATTES`) foi considerado como fonte canônica.
2. **Estratégia de Herança (Tabela por Subclasse / Joined-Table):**
   * A superclasse define a chave primária `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
   * As subclasses possuem a chave primária `id BIGINT PRIMARY KEY REFERENCES superclasse(id) ON DELETE CASCADE`.
   * Permite que a mesma entidade base (ex: `Pessoa`) possua múltiplos papéis/extensões (`PessoaLattes`, `Pesquisador`, `Estudante`).
3. **Estratégia Híbrida de Tipos e Domínios:**
   * **17 ENUMs Nativos:** Usados para estados, siglas e tipos com ciclo de vida fixo (`tipo_uf`, `tipo_sexo`, `tipo_status_ciclo`, `tipo_modalidade_banca`, etc.).
   * **14 Tabelas de Domínio:** Usadas para taxonomias acadêmicas e operacionais que podem expandir (`tipo_formacao`, `nivel_treinamento`, `tipo_acao`, `programa`, etc.).
4. **Tipos de Dados:**
   * Textos: `TEXT` para todos os atributos textuais, prevenindo quebras no ETL.
   * Datas: Convertidos de tipos primitivos errôneos no UML (`int`/`String`) para `DATE`.
   * Chaves: `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
5. **Tabelas de Junção N:N e Classes de Associação:**
   * **Classes de Associação / Associative do Modelo:** Criadas com `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` (`parceria_grupo`, `membro_projeto`, `fomento_projeto`, `participacao_evento`, `proficiencia_idioma`).
   * **Tabelas de Junção N:N Puras:** Criadas sem coluna `id`, com chave primária composta `PRIMARY KEY (fk_a, fk_b)`.

## 3. Correções Críticas de Modelagem Aplicadas

1. **Email Único e Exclusivo:** Mantida uma única tabela `unificado.email` com `CHECK ((id_pessoa IS NOT NULL AND id_grupo_pesquisa_cnpq IS NULL) OR (id_pessoa IS NULL AND id_grupo_pesquisa_cnpq IS NOT NULL))`.
2. **Campus em Projeto de Pesquisa:** Removida a FK duplicada de organização genérica, mantendo apenas `id_campus REFERENCES organizacao(id)`.
3. **Múltiplos Avaliadores na Banca:** `banca_examinadora` referencia um único candidato (`id_candidato`), e os avaliadores foram modelados na tabela de junção `membro_banca_examinadora`.
4. **Hierarquia de Áreas:** `area_atuacao` possui `id_grande_area NOT NULL REFERENCES grande_area(id)`.
5. **Identificadores de Origem:** `acao.id_origem`, `projeto_pesquisa.id_origem` e `orientacao.id_origem` preservam os IDs das fontes legadas sem colidir com as novas PKs.
